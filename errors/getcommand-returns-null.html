Paper and Spigot plugin.yml errors

"Cannot invoke PluginCommand.setExecutor ... because getCommand(String) is null"

Server log
[MyPlugin] Enabling MyPlugin v1.0
Error occurred while enabling MyPlugin v1.0 (Is it up to date?)
java.lang.NullPointerException: Cannot invoke "org.bukkit.command.PluginCommand.setExecutor(org.bukkit.command.CommandExecutor)" because the return value of "com.example.MyPlugin.getCommand(String)" is null
	at com.example.MyPlugin.onEnable(MyPlugin.java:8)
[MyPlugin] Disabling MyPlugin v1.0

What it means

Your code asked for a command with getCommand("name"), but the server does not know a command with that name, so it got nothing back. The plugin loads, crashes in onEnable() and is disabled right away. The server itself keeps running, but none of that plugin's features work.

The "Is it up to date?" part is a generic hint the server adds to every crash during enabling. Here the plugin is not outdated; the problem is in plugin.yml.

What causes it

For a plugin that uses plugin.yml, getCommand() only returns commands listed in its commands: section. The usual reasons:

  • the command is used in code but was never added to plugin.yml;
  • the name differs, for example getCommand("spawnShop") in code and spawnshop: in the file, or a typo;
  • the command is written under the wrong indentation, so it is not inside commands:.

How to fix it

Add the command to plugin.yml with exactly the same name your code uses:

commands:
  spawnshop:
    description: Opens the spawn shop
    usage: /spawnshop

Rebuild the jar and restart the server. If you add commands at runtime and do not want them in plugin.yml, check the result for null before calling setExecutor, so one missing command does not take the whole plugin down.
