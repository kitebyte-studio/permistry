Paper and Spigot plugin.yml errors

"java.lang.NoClassDefFoundError" when the plugin is enabled

Server log
[ShopPlugin] Enabling ShopPlugin v1.0
Error occurred while enabling ShopPlugin v1.0 (Is it up to date?)
java.lang.NoClassDefFoundError: com/example/lib/Helper
	at ShopPlugin.jar//com.example.shop.ShopPlugin.onEnable(ShopPlugin.java:4)
Caused by: java.lang.ClassNotFoundException: com.example.lib.Helper
[ShopPlugin] Disabling ShopPlugin v1.0

What it means

The plugin was compiled against a class that is not there when the server runs it. Compiling worked because the library was on your build classpath, but it never made it into the jar. The plugin loads, crashes in onEnable() (or later, the first time that code runs) and is disabled. The server keeps running.

The class name after NoClassDefFoundError tells you which library is missing. The "Is it up to date?" part is a generic hint the server adds to every crash during enabling.

What causes it

  • a library is added as a normal dependency (implementation in Gradle, compile scope in Maven) but the build makes a plain jar, so the library classes are not packed in;
  • you copied the wrong file from build/libs or target: the small jar instead of the one with -all or the shaded one;
  • the library belongs to another plugin (an API jar marked compileOnly / provided), but that plugin is not installed or is not in depend:, so it loads after yours or not at all.

How to fix it

Pick one of these, depending on the library:

  • Shade it. With Gradle, apply the Shadow plugin and copy the -all jar to the server. With Maven, add maven-shade-plugin. Relocate the package so it does not clash with other plugins that ship the same library.
  • Let the server download it. For libraries on Maven Central, list them in plugin.yml and keep them out of the jar: 
    libraries:
  - com.example:helper-lib:1.2.0
  • It comes from another plugin. Install that plugin and add it to depend: (or softdepend: if your plugin can work without it), so it is loaded first.

To see what is really in the jar, open it as a zip and look for the missing class path, for example com/example/lib/Helper.class.
